# PTY test contracts and measurements: issue #29

This change addresses [issue #29](https://github.com/kjelly/hufu/issues/29).
It changes tests only. The comparison baseline is `6ca6f6d668b804ad7ed19e6e4c184b73e2126a85`;
the PR is based on `12b02231d4769efe5f90b4df87df106e59afd46e`, whose intervening
changes remove unrelated context/team duplicates and add their validation notes.
The measured CLI/TUI production code is unchanged between these bases.

## Contract preservation

| Previous case | Replacement and assertion |
| --- | --- |
| BuildBinary | Removed size heuristic; real CLI invocations still require the shared binary to build and execute. |
| VersionOutput, HelpOutput, ListCommand | Keep real PTY transport, require exit 0 and specific version/help/empty-discovery output. |
| DoctorCommand | Local HTTP model-list fixture, isolated registered workspace and config; HTTP 200 requires exit 0 and the warnings summary (no teams); HTTP 503 requires exit 1 and the provider diagnostic. |
| Signal_SIGINT, TerminalRecovery, AltScreenEntry | TUILifecycle waits for an actual blocked provider request, alternate-screen entry and rendered prompt before sending signals. The first SIGINT must persist a durable wrap-up checkpoint; the second must exit 130. Alternate-screen exit must follow entry. |
| Resize_NoDeadlock, NarrowTerminal_NoCrash, RapidResize | The same PTY lifecycle sends real kernel window-size changes after readiness, requires a fresh narrow warning, expands again and requires a fresh rendered prompt. It checks the single process waiter's completion channel at each stage and then proves responsiveness through SIGINT. |
| TranscriptSample | Replaced log-only inspection with mandatory rendered-prompt readiness in TUILifecycle. |
| NoHangOnExit, StdinPipe | NonInteractiveVersion retains separate null-stdin and actual pipe cases, checking bounded exit 0 and version output. VersionOutput retains the PTY distinction. |
| IsolatedEnvironment | Config-list subprocesses first read two synthetic profile sentinels from HOME and CWD, then require exactly an empty profile list with fresh HOME/CWD. Both exit codes must be 0. |
| Size/render combinations | ResizeRenderingContract drives Update/WindowSizeMsg and View directly: old dimensions, 1x1, narrow recovery, and 20 successive sizes. It asserts applied dimensions, viewport readiness, narrow warnings and recovered prompt rendering. |

All children have isolated HOME, XDG roots, state root and CWD. No inherited
provider credentials are passed. The provider fixtures bind loopback and never
call a model or the Internet. The PTY reader uses the existing locked buffer;
one goroutine owns Wait, and completion channels synchronize the result.
Output assertions reject empty expected text, use bounded polling and fail on a
drained stream missing the expected output. Fresh-frame assertions use a byte
offset so a pre-resize frame cannot satisfy a post-resize assertion. Cleanup
kills/reaps children and joins the output reader, including failed assertions.
There are no fixed startup/resize sleeps in this file.

## Repeated measurements

Runner: Linux x86_64, kernel 6.18.55, AMD EPYC 9V74, 5 visible CPUs.
Go 1.27.2, default GOMAXPROCS (5) in the test runner, CGO_ENABLED=1;
PTY children explicitly use GOMAXPROCS=2. Shared configured build/module caches
were preserved. No other validation ran during these measurements. Each tree
was run once to warm its build cache, then three times with fresh test execution:

```sh
go test -json -count=1 -run '^TestE2E_' -timeout 5m ./cmd/hufu
go test -race -json -count=1 -run '^TestE2E_' -timeout 5m ./cmd/hufu
```

Each execution is a separate `go test` process. Wall times include package
loading, shared CLI build, execution and cleanup. Package times come from the
final package event, not a sum of overlapping parent/child events.
The existing shared CLI helper builds a normal child executable in both modes;
`-race` instruments the test runner, fixture, PTY reader and waiter state,
not the separate CLI executable.

| --- | --- | --- | --- |
| Normal/baseline | 9.195, 9.378, 9.306 | 9.306 | 7.319, 7.455, 7.328 |
| Normal/updated | 5.953, 6.040, 6.088 | 6.040 | 4.052, 4.119, 4.188 |
| Race/baseline | 11.068, 11.502, 11.235 | 11.235 | 8.510, 8.693, 8.688 |
| Race/updated | 7.785, 7.855, 8.134 | 7.855 | 5.153, 5.284, 5.446 |

All three measured executions per tree/mode passed with zero failures/skips:
16 baseline test pass events versus 14 updated events (including subtests).
The filter includes the unchanged ChatUI_TurnsCancelAndExit integration case.
The case set intentionally changes: redundant launches disappear, doctor gains
two subtests, isolation gains controls, and rendering gains a separate pure
Update/View matrix. That matrix is excluded from the `TestE2E_` timing filter;
it is included in package regression validation. These numbers describe this
focused suite, not an equal-case or whole-repository speedup. No cold-cache,
result-cache or runner CPU-cost improvement is claimed. Three repetitions
establish no observed flakes, not a bound on flake probability.

The sandbox requires network permission even for a loopback listener. An initial
sandboxed exploratory run skipped the existing fake-provider cases and is
excluded from this table. All reported runs grant loopback listening and have
zero skipped cases. The unchanged baseline still contains its original
localhost/nonexistent-provider assumptions; the updated tests remove them.

## Fault injection procedure

Mutations run only in independent archive copies of the baseline, with the two
updated test files overlaid. The final checkout and shared module cache stay
unchanged. Each copy runs:

```sh
go test -json -count=1 -run '^TestE2E_TUILifecycle$' -timeout 2m ./cmd/hufu
```

For restore, copy `charm.land/bubbletea/v2@v2.1.0` to a private directory and
add a local `replace` in the snapshot's go.mod. In `cursed_renderer.go`, remove
`enableAltScreen(s, false, true)` only from `cursedRenderer.close`. Entry and
all other behavior remain intact. The target test exits nonzero with
`terminal did not leave alternate screen after SIGINT`, after successful
readiness, resize and exit-130 assertions.

For entry, set `v.AltScreen = false` in `internal/tui/dashboard_view.go`.
The target test exits nonzero because the required entry sequence is absent;
it can no longer accept inline rendering or an early exit as success.

For provider failure, change the blocked TUI's provider URL path from `/v1` to
`/broken` while leaving the local fixture alive. The target test exits nonzero
with `TUI never reached the blocking provider`; it cannot mistake pre-TUI
provider errors for a passing terminal test.

### Resize after successful initial readiness

A separate resize mutation preserves the first WindowSizeMsg and ignores only
later ones: add `if m.width > 0 { return m, nil }` at the start of that Update
case. Run both target tests:

```sh
go test -json -count=1 -run '^(TestE2E_TUILifecycle|TestResizeRenderingContract)$' -timeout 2m ./cmd/hufu ./internal/tui
```

The PTY reaches provider, alternate-screen and prompt readiness, then fails with
`PTY output missing "Terminal too narrow" after 10s`. The pure rendering test
also fails with `resize not applied`. Thus the resize check detects a broken
post-startup resize path, independently of startup readiness. All injected faults
are absent from the final tree; ordinary, race and CGO-disabled package tests
above passed on the unmodified production implementation.
